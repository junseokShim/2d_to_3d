# AI 마모 감지 설계 (Tool3D)

## 결론
**PatchCore (ImageNet 사전학습 ResNet18, layer2+3 특징) + 같은 공구의 비마모 영역으로 만든 메모리 뱅크.** 오프라인 ONNX(onnxruntime-web wasm)로 앱 안에서 실행. 실패 또는 저신뢰 시 기존(classic) 방식으로 자동 전환.

## 후보 비교
| 방식 | 마모 라벨 필요 | 오프라인/폰 | 판단 |
|---|---|---|---|
| **PatchCore** (anomalib 계열) | 불필요 (정상 영역만) | ResNet18 11 MB, 가능 | **채택**: 라벨 없이 시작, 공구마다 자기 정상면을 기준으로 삼음 |
| EfficientAD | 불필요, 단 공구별 사전 학습 필요 | 가능 | 공구 종류마다 학습 필요 → 보류 |
| SAM / MobileSAM / EfficientSAM | 불필요 (프롬프트) | MobileSAM ~40 MB | 영역 분할은 좋지만 "마모인지" 판단은 못함 → 여유면 마스크 보조용 후보 |
| DINOv2 few-shot | 수 장 | ViT-S 85 MB+ | 폰 속도·용량 부담 → 서버/PC 버전 후보 |
| 공개 공구마모 데이터셋 fine-tune (Mendeley, Kaggle, NASA milling) | 필요 (데이터셋) | 가능 | 촬영 조건 차이 큼 → 실제 사진 확보 후 2단계 |

## 동작
1. 기존 기하 처리로 정렬, px/mm(공구경 기준), 절삭날 위치 산출
2. 절삭날 옆 여유면 띠만 AI 판정 대상 (실루엣·배경 제외), 반사광(glint) 게이트
3. 같은 사진의 비마모 몸체 패치로 메모리 뱅크 → 점수 분포 상위 분위수 + 여유로 임계값
4. 마모 마스크 → 기존 VB(ISO 8688-2)·면적·체적 계산 그대로

## 검증 현황
- 합성 마모 이미지: VBmax 오차 ≤ 0.06 mm, 비마모 공구 오탐 0 (`test/wear/ai-run.js` 8/8)
- 실제 마모 공구 사진 + 알리코나 기준값으로는 **미검증**
